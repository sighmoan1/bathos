# Inbound Webmentions

Reviewed source versions hash the complete HTML after native HTMLRewriter removes script and template elements. Changing injected challenge scripts does not invalidate an unchanged article's approval. Body text, metadata, markup and backlink attributes remain in the version; changes require review, and a removed live backlink retracts the response. Script/template content cannot supply a backlink and is never executed.

This separate Worker implements issue #39 and receiver abuse controls from #41. The default development configuration stays disabled. The explicit production target, deployment guard, dedicated database, migration ledger and protected operator handoff are documented in [PRODUCTION.md](PRODUCTION.md). It does not share the admin OAuth Worker's credentials.

## Deployment prerequisites

1. Identify the authenticated Cloudflare account, dedicated D1 database within existing account limits, database UUID, and deployment/operator permissions. For a new installation, bind that database as `DB` and apply `migrations/0001_webmentions.sql` through the normal deployment process. For the existing production database, follow PRODUCTION.md and its migration ledger; do not reapply the raw initial schema. A migration creates tables and must first be rehearsed against a separate local database.
2. Configure independent `MODERATOR_TOKEN` and `RATE_SALT` secrets (each at least 32 characters) via Wrangler's secure interactive secret workflow. Never put these values in the client, tracked files or command arguments. Token rotation invalidates old moderator access; salt rotation changes the anonymized rate buckets.
3. Assign **only** `bathos.org/api/webmention*` to this Worker. The existing `bathos-admin-oauth` owns `bathos.org/api/*`; inspect current routes and confirm that Cloudflare's more-specific Webmention route wins before enabling. Do not replace or remove the OAuth route. Leave `workers_dev` disabled. The committed cron runs each minute for revalidation and rate-counter cleanup; verify the deployed trigger. Confirm usage/cost and database capacity with the existing account configuration before adding resources.
4. Set `ENABLED=true` only after local tests, the repository's frozen dependency installs and `pnpm verify:release`, exact-head Pages check, operator credentials, D1 migrations, DNS/egress controls and route ownership are verified. Deployment and production smoke verification remain separate gates. `npm run check` validates packaging, not remote readiness.
5. Publish Webmention endpoint discovery on Bathos only after a successful production form POST, moderator approval, response read and deletion/retraction smoke test. If unconfigured, keep endpoint discovery absent. A configured Worker without its DB/salts/token fails closed with 503.

## API

- `POST /api/webmention`: `application/x-www-form-urlencoded`, exactly one `source` and `target`; accepts published canonical `https://bathos.org/posts/<slug>/` targets. Returns 202 after synchronous verification/pending storage; 200 `removed` for a removed source/backlink. A deleted target is rejected. Network failures never count as deletion.
- `GET /api/webmention/responses?target=<canonical URL>`: `{responses:[{source,target,name,author,published}]}`. Only approved records with verification younger than 24 hours. Optional strings are bounded plain text, never remote markup. Consumers must render text, validate links, and set `rel="nofollow ugc noopener noreferrer"`.
- `GET /api/webmention/admin` with `Authorization: Bearer <MODERATOR_TOKEN>` lists up to 100 records including state, ordered by latest update then source/target. Use optional `?offset=0..999` (default 0) to review older records; the response includes `offset` and `nextOffset` (`null` at the last bounded page). Duplicate, negative, non-integer and out-of-range offsets return 400. Pagination retains the same authentication and persistent read limits. Pages use a live snapshot, so restart from offset 0 if records change during review. Inspect the external source before approving. This is an operator API; do not place its token in the public manager.
- `POST /api/webmention/admin` with that bearer header and JSON `{source,target,state,fingerprint}` accepts `approved`, `rejected` or `delete`. Approval requires the fingerprint returned in the reviewed admin listing, and fetches source/target again and rejects changed content with 409. Receive the update and review it again. Rejection persists for unchanged re-submissions. Source changes return to pending; a removed backlink retracts any state.

All responses use `Cache-Control: no-store`; CORS permits only the configured Bathos origin. Cross-origin form submission needs no browser read access. There is no credentialed CORS or cookie authentication. Unknown paths/methods are refused. SQL values are bound parameters.

## Bounds and abuse controls

Forms/JSON: 8 KiB; source and target HTML: 256 KiB each; URLs: 2,048 characters; metadata: title 200 and author 100 characters; redirects: 3; complete DNS/fetch/body operation timeout: 8 seconds per URL. Only HTTP/HTTPS, standard ports, no credentials, fragments, IP literals, local/reserved hosts. Both A and AAAA are checked via Cloudflare DoH before each fetch and redirect; all returned addresses must be public unicast. No user cookies, bearer tokens, or request headers are forwarded.

D1 atomic limits are persistent across isolates: 20 submissions per hashed client IP/minute, 30/source-host/hour and 200 globally/hour. Cloudflare's trusted `CF-Connecting-IP` is required. The salt prevents dictionary lookup of IP hashes. At most 1,000 records; unique source/target entries update idempotently at capacity. No in-memory fallback when D1 fails. Rate errors return 429 and a conservative `Retry-After`. Cleanup deletes expired buckets on scheduled runs; monitor D1 storage and errors. Public/admin reads have persistent limits of 60/client/minute and 10,000 globally/hour; add account WAF controls as additional defense.

Approved responses have a 24-hour lease. The scheduled handler rechecks the least recently attempted approved record, retracts removed backlinks and returns changed content to pending. Every attempt advances a separate scheduling timestamp, including failures, so an unreachable source cannot starve other records. An unverifiable record's lease is not renewed. A missing cron hides stale responses safely. At maximum quota, the one-minute schedule covers 1,000 records in 16.7 hours. One verification uses at most 24 external subrequests (target and source, four hops each with two DNS queries and one fetch), leaving headroom below a 50-subrequest account limit for D1. Monitor lease expiration and runtime/cron failures.

**Residual DNS constraint:** Workers `fetch()` resolves hostnames independently of the DoH preflight; it cannot pin the checked IP while preserving TLS/Host. DNS changes between preflight and fetch remain possible. The Worker explicitly sets `global_fetch_strictly_public`, uses global fetch, and has no VPC/service/network bindings. Cloudflare's production outbound proxy verifies public Internet destinations; the flag also prevents own-zone origin bypass. This platform boundary closes private-network egress that DNS preflight alone cannot guarantee. Preflight remains defense in depth, not proof against rebinding. Local Miniflare does not establish the production network boundary. Do not port to another runtime without equivalent egress enforcement. See [Workers security model](https://developers.cloudflare.com/workers/reference/security-model/) and [strictly public fetch](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#global-fetch-strictly-public). Do not trust DNS failures or HTTP errors as backlink deletion.

## Local validation

`npm ci --prefix workers/webmention` then `npm test --prefix workers/webmention`. Tests run the packaged Worker in Miniflare with real HTMLRewriter and local D1, and mock only external HTTP/DNS. No remote bindings or paid resources are used. Miniflare and the bundler are explicit pinned development dependencies. New Worker tests are intentionally independent of the existing OAuth package; the coordinator's #42 integration adds them to the release gate.
